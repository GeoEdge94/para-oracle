# M2 — IPFS pinning + resolution_script standalone + web3_publisher

**Date** : 2026-04-22
**Statut** : ✅ Implémenté, testé unitaire + E2E Docker (avec tamper test).

## Objectif

Ancrer chaque résolution dans 3 CIDs IPFS auditables : `data.json` (le manifest),
`resolution_script.py` (code de vérification public), `schema_v1.json` (schéma
versionné). Fournir un script standalone que n'importe qui peut exécuter pour
vérifier une résolution sans accès au backend.

## Fichiers créés

- [backend/app/services/ipfs_client.py](../../backend/app/services/ipfs_client.py)
  — `IPFSClient` avec 2 backends : `mock` (CID déterministe SHA-256, écrit dans
  `data/ipfs-mock/<cid>`) et `pinata` (POST Pinata API avec JWT). API :
  `pin_bytes`, `pin_file`, `pin_json`, `cat_bytes`, `gateway_link`.
- [scripts/resolution_script.py](../../scripts/resolution_script.py)
  — script public **stdlib-only**, zéro import `app.*`. Prend un `data.json`,
  recompute le fingerprint canonique, vérifie vs `--expected-fingerprint`,
  applique le seuil selon `direction`, imprime le résultat JSON. Exit codes :
  0=OK, 1=mismatch fingerprint, 2=erreur structurelle.
- [scripts/tests/test_resolution_script.py](../../scripts/tests/test_resolution_script.py)
  — 9 tests subprocess : happy path, match backend canonical, expected match/mismatch,
  override threshold/direction, schema invalide, champs manquants, manifest spectral.
- [backend/app/services/web3_publisher.py](../../backend/app/services/web3_publisher.py)
  — orchestrateur : pin blobs → injecter CIDs dans manifest → canonicalize → pin
  `data.json` + `resolution_script.py` + `schema_v1.json` → retourne `PublishBundle`.
  Désactivable via `USE_WEB3_PUBLISHING=false`.

## Choix techniques

- **Mock IPFS = content-addressed + disque** : le CID mock est
  `"bafybei" + sha256(content)[:52]`. Le contenu est écrit dans
  `DATA_DIR/ipfs-mock/<cid>`. Cela permet à `cat_bytes(cid)` de simuler un
  fetch gateway local et rend les tests E2E fiables sans quota externe. Le
  préfixe `bafybei` reste shape-compatible avec un CIDv1 base32 réel.
- **Fingerprint post-injection pour spectral** : le fingerprint M1 de
  `para-deforestation-2025-s1` était `a413bdab…` (rasters avec `cid=null`).
  Après injection des 4 CIDs dans `fingerprint_inputs.rasters[]`, le fingerprint
  devient `16be290b…` — le **final** qui sera soumis on-chain en M3. Pour
  weather, aucun blob → fingerprint M2 = fingerprint M1 (inchangé).
- **resolution_script.py stdlib-only** : duplication de `_round_floats` et
  `canonicalize` (nécessaire par design — le script doit être auditable sans le
  backend). Le test `test_fingerprint_matches_backend_canonical` garantit que les
  deux implémentations restent byte-identiques.
- **Pin de `resolution_script.py` et `schema_v1.json` à chaque résolution** : pas
  de cache MVP. Pinata et mock dédupent par contenu → même CID retourné à chaque
  pin. Quota Pinata free tier (500 pins/mois) largement suffisant pour dev.
- **Double-write `ipfs_cid = data_cid`** : les frontends existants lisent encore
  `ipfs_cid`. Quand `USE_WEB3_PUBLISHING=true`, on aliaise ; quand `false`, on
  conserve le mock CID legacy du pipeline. Nettoyage en M4.
- **Résolution du path `resolution_script.py`** : tentative `/scripts/` (Docker)
  puis chemin remontant depuis `backend/app/services/` (dev local). Utilise la
  première qui existe.

### Tamper test

Modifier `observed_value` dans `data.json` pinné →
`resolution_script.py --expected-fingerprint <original>` retourne :
- `exit code 1`
- `fingerprint_verified: False`
- `fingerprint_verify_detail: mismatch`
- Nouveau fingerprint recomputé, différent de l'original

✅ Détection de falsification fonctionnelle bout-en-bout.

### Vérification DB

```sql
SELECT b.slug, a.fingerprint_sha256, a.data_cid, a.script_cid, a.schema_cid,
       a.ipfs_cid = a.data_cid AS ipfs_alias_ok
  FROM analyses a JOIN bets b ON a.bet_id=b.id
 WHERE b.slug IN ('precip-amoy-testnet-01','para-deforestation-2025-s1');
```
Les 3 CIDs sont non-null, `fingerprint_sha256` renseigné, `ipfs_cid == data_cid`
pour les 2 lignes.

  À faire en M4 (liens cliquables vers gateway).
